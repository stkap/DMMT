# Dynamic Micro-Matrix Trees (DMMT) 🌳

![Language](https://img.shields.io/badge/language-C++-blue.svg)
![License](https://img.shields.io/badge/license-MIT-green.svg)
![Platform](https://img.shields.io/badge/platform-Edge%20%7C%20Microcontrollers-lightgrey.svg)

**DMMT** is a lightweight, gradient-free continuous learning architecture designed specifically for Edge AI and microcontrollers (e.g., ESP32) with strict SRAM limitations (< 300 KB). 

It entirely eliminates the need for the Backpropagation algorithm, resolving the catastrophic forgetting problem through organic topological growth (Mitosis) and preventing memory overflow via a deterministic memory refactoring mechanism (Algorithm of Sleep).

## 🚀 Key Features
* **No Backpropagation:** Uses Topological Backpropagation and Traceback Learning (Oja's Rule) on the active path.
* **$O(1)$ Training Complexity:** Only the nodes on the active routing path are updated.
* **Zero Catastrophic Forgetting:** Network topology grows dynamically to adapt to new patterns (anomalies or systematic defects) without overwriting learned weights.
* **Deterministic Memory:** Strictly 256 bytes per node. Uses a linear Bump Allocator to completely eliminate heap fragmentation.

## 🛠️ How to Build & Run

The project is written in standard C++ and has zero external dependencies, making it extremely easy to build for both desktop profiling and microcontroller deployment.

**For Windows Developers:**
The source code is perfectly tailored for a native Windows 11 environment. You can compile the project seamlessly using Visual Studio Community 2022. 
1. Clone the repository.
2. Open the solution file (`.sln`) in Visual Studio.
3. Set the build configuration to `Release` for accurate performance profiling.
4. Build and run. The profiler will automatically output the memory footprint logs to the console and generate a CSV file.

**For GCC / Clang:**
```bash
g++ -O3 src/main.cpp -o dmmt_profiler
./dmmt_profiler
```

When the memory limit is reached, the Algorithm of Sleep (Topological Refactoring) is triggered. It utilizes Apoptosis (pruning noise) and Branch Merging (crystallizing systematic defects into a single node) to recover 99.9% of memory and halt memory leakage entirely.

Phase 1: Without Branch Merging

Memory grows linearly due to micro-fluctuations in the unmerged systematic defect.

Phase 2: With Apoptosis and Merging Enabled

The engine crystallizes the defect into a single node. The new baseline remains perfectly flat, completely halting memory leakage.
